# Operational Inference Acceptance Protocol v1

상태: protocol v1 · 구현 결과를 보기 전에 고정

이 문서는 연구에서 검증한 모델을 운영 분석 경로(순차 입력 → 모델 추론 → 결과 저장 → 화면)로 옮길 때
**무엇을 보면 합격인지**를 결과를 보기 전에 고정합니다. 대상은 두 검증 사례입니다.

- **XJTU-SY 베어링** — 획득(acquisition) 순차 입력의 이상 점수와 RUL 추정
- **AI-Hub 239 공기압축기** — 1분 다변량 전력 시계열의 이상 탐지

이 문서는 합격 기준만 소유합니다. 모델 패키지·분석 입력·결과의 계약은 운영 분석 ADR이, 원본 데이터 사실은
[XJTU source profile](xjtu-source-profile.md)과 [AI-Hub source profile](aihub-239-source-profile.md)이,
RUL target·split·leakage 규칙은 [XJTU RUL protocol](xjtu-rul-prognostics-protocol.md)이 소유합니다.

갱신 규칙: 결과를 본 뒤 임계값·평가 집단·주입 조건을 바꾸지 않습니다. 바꿔야 하면 v2를 만들고 v1 결과를
그대로 보존합니다.

## 1. 공통 원칙

1. **순차 입력은 미래를 모른다.** 단계 `k`의 출력은 단계 `k`까지 공급된 입력과 모델 패키지만으로 계산합니다.
   전체 수명 길이 `N`, 이후 획득, 보류 기간 통계를 입력·정규화·임계값에 쓰지 않습니다.
2. **순차 결과 = 일괄 결과.** 같은 모델 패키지로 단계별로 계산한 출력과 같은 입력을 한 번에 계산한 출력이
   일치해야 합니다. 일괄 계산이 미래 데이터를 쓰지 않았다는 증거이기도 합니다.
3. **미래 변경 불변.** 단계 `k` 이후 입력을 바꾸거나 제거해도 단계 `k`까지의 출력은 바뀌지 않아야 합니다.
4. **재시작 연속성.** 순차 입력 도중 Supervisor를 강제로 재시작해도 (설비, 단계, 모델 패키지)별 결과가 정확히
   한 번 저장되고, 공급한 단계 집합과 처리한 단계 집합(처리 또는 이유 있는 skip)이 같아야 합니다.
5. **재생 표시.** 기록 데이터 재생 결과는 원본 event 시각과 처리 시각을 따로 저장하고 재생임을 기록합니다.

## 2. XJTU-SY

### 2.1 모델 패키지와 재생 대상

운영 모델 패키지는 기존 fold-1 연구 설정을 train 베어링으로 다시 학습해 만듭니다. 설정은 연구 manifest를
그대로 사용하고 새 hyperparameter를 도입하지 않습니다.

| 패키지 | 연구 설정 | 출력 |
| --- | --- | --- |
| Isolation Forest 이상 점수 | `xjtu-sy-iforest-fold-1-finalized-v1` | 획득별 이상 점수 |
| Ridge RUL | `xjtu-sy-rul-feature-ridge-fold-1-v1` | 획득별 RUL (acquisition-interval) |
| LSTM Autoencoder | `xjtu-sy-lstm-autoencoder-fold-1-development-v1` | 시퀀스 오른쪽 끝 획득의 재구성 점수 |
| LSTM RUL | `xjtu-sy-rul-lstm-fold-1-v1` | 시퀀스 오른쪽 끝 획득의 RUL |

재생 대상은 fit에 쓰지 않은 fold-1 validation(`Bearing1_2`, `Bearing2_2`, `Bearing3_2`)과 held-out
(`Bearing1_1`, `Bearing2_1`, `Bearing3_1`) 베어링뿐입니다. train 베어링 재생은 in-sample이므로 합격 근거로
쓰지 않습니다.

### 2.2 저장된 연구 결과와의 일치

| 패키지 | 비교 대상 | 허용오차 |
| --- | --- | --- |
| Isolation Forest | `xjtu-sy-iforest-fold-1-holdout-v1.json`의 베어링별 Spearman ρ, late-vs-middle 확률 (운영 단계 출력으로 다시 계산) | 절대 차이 ≤ 1e-9 |
| Ridge RUL | `xjtu-sy-rul-three-model-fold-1-validation-v1.json`의 획득별 예측 | 획득별 절대 차이 ≤ 1e-6 acquisition-interval |
| LSTM RUL | 같은 validation 결과와 `xjtu-sy-rul-lstm-fold-1-benchmark-v1.json`의 획득별 예측 | 획득별 절대 차이 ≤ 1e-3 acquisition-interval |
| LSTM Autoencoder | `xjtu-sy-lstm-autoencoder-fold-1-development-v1.json`의 베어링별 통계 | 절대 차이 ≤ 1e-6 |

연구 결과는 torch `2.14.0` CPU, deterministic algorithms로 만들어졌습니다. 같은 runtime에서 허용오차를 넘으면
허용오차를 늘리지 않고 원인을 찾아 기록합니다.

### 2.3 RUL 표시 범위

- 단위는 `acquisition-interval`로 저장합니다. XJTU-SY의 공식 획득 주기(1분)로 분 단위를 함께 표시할 수 있지만
  별도 target을 만들지 않습니다.
- 종료점 의미는 `last-recorded-acquisition`이며 물리 고장 시각이 아닙니다.
- 검증 오차는 연구 결과의 베어링별 MAE·편향을 그대로 표시합니다. RUL v1은 불확실성 구간을 검증하지 않았으므로
  신뢰구간을 표시하지 않습니다.
- 학습 조건(35Hz12kN, 37.5Hz11kN, 40Hz10kN) 밖의 입력은 적용 범위 밖으로 표시합니다.

## 3. AI-Hub 239 공기압축기

### 3.1 정답이 없다는 사실에서 출발

AI-Hub 239에는 이상·고장의 정답이 없습니다. SOH 라벨은 역률·고조파 임계값으로 매긴 **전력품질 등급**이므로
이상 탐지 평가 정답으로 쓰면 임계값 규칙을 다시 맞히는 순환 평가가 됩니다. 기동패턴 라벨은 운전 조건이며
이상 여부가 아닙니다. 따라서 v1은 다음 두 가지만 측정합니다.

1. **주입 없는 보류 기간의 경보 비율** — 원본을 바꾸지 않은 보류 기간에서 검토 구간으로 판정된 윈도우 비율.
   실제 이상이 섞여 있을 수 있으므로 "오경보율"이라고 부르지 않습니다.
2. **주입 이상 탐지율과 지연** — 보류 기간 원본에 알려진 변화를 넣었을 때 검토 구간이 생기는지와 그 지연.

AI-Hub RUL은 수명·고장 사건 정보가 없으므로 제공하지 않습니다.

### 3.2 데이터 분할

- Training/raw(filekey 44031)와 Validation/raw(44051)는 같은 72대의 서로 다른 기간입니다.
- **학습**: 각 설비의 Training/raw 기간. 모델 패키지는 설비별로 그 설비의 학습 기간만으로 fit합니다.
- **보류**: 같은 설비의 Validation/raw 기간. 임계값·스케일러·운전 구간 기준을 보류 기간에서 fit하지 않습니다.
- **개발 설비**: reference asset device 1338(`SourceData_16`)과 seed `239`로 고른 적격 설비 5대. 모델 후보 선택과
  windowing·특징 결정에만 사용합니다.
- **평가 설비**: 나머지 적격 설비 전체. 후보를 고정한 뒤 한 번만 평가합니다.
- **적격 조건**: semantics-v3에서 상전류·상전압·주파수가 확정된 member(`SourceData_135` 제외), 학습 기간에
  상전류 1 A 이상 timestamp 2,880개(48시간) 이상, 보류 기간에 1,440개(24시간) 이상.

### 3.3 입력과 운전 조건

- 채널: R/S/T상전류, R/S/T상전압, 주파수. semantics-v3 미확정 채널(전력·역률·고조파·온도)은 쓰지 않습니다.
- 윈도우: 5분(60초 cadence에서 timestamp 5개). 탐지 지연 기준(§3.5)과 맞물려 있으므로 개발 설비에서 바꾸지 않습니다.
- 운전 조건은 라벨 없이 전류로 나눕니다. 전류평균 1 A 미만 timestamp는 "정지"로 평가에서 제외하고 그 사실을
  결과에 남깁니다. 기동패턴 라벨은 이 구분과의 일치율 확인에만 씁니다.
- 결측·충돌 timestamp는 채우지 않고 제외하며 제외 수를 결과에 남깁니다.

### 3.4 모델 후보와 선택

후보는 두 가지입니다. 개발 설비의 보류 기간 주입 평가(§3.5)로 하나를 고르고, 동률이면 변수별 근거를 제공하는
모델을 고릅니다.

| 후보 | 변수별 근거 |
| --- | --- |
| Isolation Forest (#522의 기준 패턴 이탈 점수를 고정 패키지로 승격) | 제공하지 않음 |
| PCA 재구성 잔차(SPE) | 특징별 잔차 기여도 제공 |

검토 구간 규칙: 패키지 임계값은 학습 기간 점수의 99.5% 분위수입니다. 임계값을 넘은 윈도우가 2개 이상 연속되면
검토 구간을 열고, 1개 윈도우 이하의 틈은 같은 구간으로 잇습니다.

### 3.5 주입 이상

보류 기간의 운전 timestamp에 seed `239`로 위치를 정해 설비당 유형별 3회 주입합니다. 주입끼리 겹치지 않고
주입 사이 간격은 6시간 이상입니다.

| 유형 | 변화 | 지속 | 판정 |
| --- | --- | --- | --- |
| 상 결손 | 한 상 전류 ×0.05, 나머지 두 상 ×1.15 | 30분 | 합격 기준 |
| 전류 불평형 | 한 상 전류 ×1.25 | 30분 | 합격 기준 |
| 전압 강하 | 한 상 전압 ×0.90 | 30분 | 합격 기준 |
| 주파수 이탈 | 주파수 +0.5 Hz | 30분 | 합격 기준 |
| 점진 부하 증가 | 세 상 전류를 6시간 동안 ×1.0→×1.3 | 6시간 | 보고만 |

**탐지**: 주입 구간과 겹치는 검토 구간이 주입 시작 후 20분 안에 열리면 탐지로 셉니다.

### 3.6 합격 기준 (평가 설비, 설비별 동일 가중 평균)

| 지표 | 기준 |
| --- | --- |
| 합격 기준 유형별 탐지율 | 각 유형 ≥ 0.90 |
| 주입 없는 보류 기간의 경보 비율 | ≤ 0.02 (평가한 운전 윈도우 대비) |
| 점진 부하 증가 | 탐지율·지연 보고, 합격 판정 없음 |

## 4. 스트리밍 지연

지연은 단계마다 다음 시각을 저장해 측정합니다: 원본 event 시각, 수신 시각, 윈도우 확정(또는 획득 공급) 시각,
분석 결과 커밋 시각, 화면 반영 시각.

| 구간 | 기준 |
| --- | --- |
| 윈도우 확정 → 분석 결과 커밋 (AI-Hub, 통상 재생 속도) | p95 ≤ 10초 |
| 획득 공급 → 분석 결과 커밋 (XJTU, Isolation Forest·Ridge) | p95 ≤ 2초 |
| 분석 결과 커밋 → 화면 반영 | polling 주기 + 2초 이하 |

화면에는 최신 관측 시각과 최신 분석 시각을 함께 표시해 사용자가 지연을 직접 볼 수 있어야 합니다.
