# 데이터부터 시작하기: 분석 바로가기

Gradio·Orange·Streamlit식 "데이터를 넣으면 무엇을 할 수 있는지 바로 안다"는 경험을 기존 Operations Web 안에서
제공합니다. Gradio로 화면을 바꾸지 않고, 이미 있는 신호 탐색·이상 탐지·AI 질문을 데이터가 들어오는 자리에서
연결합니다.

## 데이터 없는 첫 사용: 베어링 분석 체험

빈 작업공간의 **분석 체험하기**에서 **베어링 분석 체험 시작**을 선택합니다.
기존 CSV 등록과 실시간 OPC UA 예시는 함께 사용할 수 있는 별도 진입입니다.

| 사용자 질문 | 기존 화면에서 확인할 근거 |
| --- | --- |
| 어떤 기록을 조사하나? | 일정한 합성 기록·변화가 있는 합성 기록과 학습 참조의 구분 |
| 두 모델은 언제부터 다르게 보나? | Isolation Forest·LSTM 오토인코더의 실제 점수·각 모델의 기준 |
| 신호도 달라졌나? | 선택 측정의 원본 파형과 수평·수직 진동 특징 추이 |
| 전반부와 후반부는 얼마나 다른가? | 같은 특징의 A/B 분포·대표값·유효 측정 수 |
| 두 특징이 함께 변하나? | 같은 측정끼리 짝지은 산점도·상관 관계 |
| 어떤 주파수 성분이 달라졌나? | 동일 A/B 구간의 원본 파형으로 계산한 Welch 스펙트럼 |
| 무엇을 더 확인해야 하나? | 선택 모델·측정에 연결한 선택적 검토 요청과 사람의 판단 |

안내는 계산 결과를 대신 만들지 않습니다. 모델·측정·특징·구간을 바꾸면 다음 안내 링크가 현재의 유효한
선택을 이어받으며, 다른 설비의 선택을 섞지 않습니다. 기록에는 실제 측정 날짜를 만들지 않고 선언된
1분 간격에 따른 경과 시간을 표시합니다. AI 해설과 상태 전망은 선택적인 추가 탐색 기능입니다.

기본 체험은 외부 원본을 내려받지 않습니다. [`demo/bearing.py`](../../src/industrial_phm/demo/bearing.py)가
일정한 합성 참조와 별도 체험 기록 두 개를 생성합니다. 전처리·두 모델·점수 기준은 참조만으로 학습하고,
체험 기록은 학습에 사용하지 않습니다. 모델은 제품의 Isolation Forest 패키지 실행과 LSTM 오토인코더
학습·실행 코드를 사용하지만, 체험 전용 학습 설정이며 XJTU-SY 연구 패키지나 현장 검증 모델이 아닙니다.
모델 점수·특징·EDA는 정상 패키지 runner와 API가 실제로 계산합니다.

예시는 작업공간의 형제 디렉터리에 생성하며 실제 작업공간의 데이터·설정을 변경하지 않습니다.
베어링 체험에서는 분리된 작업공간에 AI 해설·검토 요청·판단 기록을 저장할 수 있고, 실시간 수신 예시는 읽기 전용입니다.
베어링 체험 작업공간은 새 데이터 연결(CSV·OPC UA·수집 제어)·모델 연결·다른 예시 시작을 서버에서 거절합니다.
준비된 기록은 재실행 후에도 다시 쓰이므로, 체험 중의 업로드가 실기록 체험에 섞이지 않게 합니다.
안내는 저장된 최신 결과가 자기 기준을 넘은 모델을 먼저 열어, 사람이 검토할 결과부터 보여 줍니다.
한 번에 한 예시만 실행합니다. 응답이 유실되면 시작을 다시 보내지 않고 상태를 확인하며,
종료 후 재실행해도 같은 예시의 분석·검토 기록을 보존합니다.

Linux 개발 환경에서 직접 실행할 때는 다음을 사용합니다.

```bash
uv run --locked --extra operations industrial-phm demo bearing
```

기본 작업공간은 `artifacts/demo-bearing`, 포트는 2719입니다. `--workspace`·`--ui-port`로 바꿀 수 있습니다.
macOS의 제품 실행은 `make up`과 Web의 체험 버튼을 사용합니다.

실제 XJTU-SY 원본이 준비된 환경의 `industrial-phm demo xjtu --until 100`도 같은 안내를 제공합니다.
이 경우 합성 입력 대신 학습에 쓰지 않은 실제 베어링의 파형과 기존 연구 설정으로 학습한 두 패키지를 사용합니다.
[원본 준비](../../data/README.md#xjtu-sy)·[실기록 실행](../../apps/README.md#이상-탐지-모니터링-xjtu-sy-기록-재생)을 따릅니다.

브라우저 회귀는 흐름·범위 유지·실제 계산·검토 저장을 확인합니다. 자동 검증이 현장 고장 진단,
모델 정확도 또는 처음 보는 운영자의 사용성 합격을 입증하지는 않습니다.

## 사용자가 할 수 있는 것
- 빈 작업공간에서 모델·EDA 체험이나 CSV 등록으로 시작하고, 운영 관리에서 OPC UA 연결을 선택합니다.
- 설비 개요와 CSV 저장 직후에 **분석 바로가기**가 있습니다. 항목마다 `이름 · 근거 · 열기`의 한 줄이고, 입력이 맞지만
  연결되지 않은 모델은 `모델 연결`, 결과를 기다리는 항목은 `대기`입니다. 이 데이터로 할 수 없는 항목은 맨 아래
  `사용 불가` 한 줄에 이유와 함께 모읍니다. 개요에서는 이미 화면에 있는 항목(진동 설비의 측정 신호)을 빼고 보여줍니다.
- `열기`는 같은 설비를 유지한 채 해당 화면을 엽니다. 구간 비교·관계·주파수 성분은 계산까지 실행하고, AI 질문은
  질문 입력 칸으로 이동합니다. `모델 연결`은 모델을 연결하는 탭으로 이동합니다.
- 문구는 안내·유도가 아니라 사실(신호 수, 획득 범위, 결과 수, 불가 이유)만 짧게 씁니다.

## 판단 기준 (서버)
`GET /api/v1/explore/capabilities?asset_id=`가 저장소에서 직접 판단하고, Web은 문장만 붙입니다.

| 항목 | `열기` (ready) | 그 밖의 상태 |
| --- | --- | --- |
| 측정 신호 | 측정 이력이 있음, 또는 분석된 진동 획득이 있음 | 파형만 있고 모델 없음 → `모델 연결` |
| 구간 비교 | 측정 이력이 두 시각 이상, 또는 분석된 획득 2개 이상 | 획득이 적음 → `대기` |
| 신호 관계 | 측정 이력 신호 2개 이상, 또는 특징 2개 이상·획득 3개 이상 | 신호가 하나 → 사용 불가 |
| 주파수 성분 | 분석된 진동 획득(원본 파형) | 시간별 측정값만 있음 → 사용 불가 |
| 상태 전망 | 유효 값 20개 이상이면 변화·기준까지 여유. 그래프의 시간 예측은 기간의 2배 이상·20개 이상 기록, 분석된 획득은 획득 개수로도 예측 | 기록이 짧음 → 사용 불가 · 파형만 있고 모델 없음 → `모델 연결` |
| 이상 탐지 | 모델 분석 결과가 있거나 CSV·OPC UA의 저장 측정 이력이 있으면 모델 없는 MAD 변화 구간 탐색 | 모델 연결을 요구하는 고급 분석은 입력 호환성 확인·연결 필요, 측정 이력이 없으면 안내 |
| AI 질문 | 운영 실행 중이고 모델 결과가 있음(이상 탐지 탭) 또는 상태 전망이 열림(상태 전망 탭) | 운영 미실행 화면 → 사용 불가(운영을 시작한 화면에서 사용) · 둘 다 없음 → 사용 불가(모델 결과·상태 전망 없음) |

CSV 측정 이력만 있어도 별도 학습 모델 없이 MAD 기반 변화 구간을 탐색할 수 있습니다. 이는 고장 판정이 아니며, 모델 바인딩 기반 이상 점수와 다릅니다. 이 목록은 분석이나 모델을 실행하지 않습니다.

## 사용자 과제로 본 합격 조건
| 과제 | 합격 | 불합격 |
| --- | --- | --- |
| 처음 사용자가 CSV를 저장한 뒤 다음 할 일을 찾음 | 저장 직후 분석 바로가기에서 구간 비교를 열어 첫 비교 결과에 도달 | 어디로 가야 할지 묻거나 모니터링 탭을 헤맴 |
| CSV만 저장한 사용자가 이상 탐지를 기대함 | 모델 없이 변화 구간 탐색을 열고 비교 기준을 선택할 수 있음 | 모델을 반드시 연결하라는 안내만 보여주거나 화면이 비어 있음 |
| 모델이 연결된 진동 설비에서 주파수 변화를 봄 | 개요의 분석 바로가기에서 한 번에 주파수 성분 그래프에 도달 | 신호 탐색에서 직접 구간과 버튼을 찾아야 함 |
| 운영 미실행 화면에서 AI 질문을 찾음 | 운영을 시작하면 가능하다는 것을 이해 | 데이터 문제로 오해 |

자동 브라우저 테스트는 위 경로가 동작하는지만 확인합니다. 실제 사용성 합격은 사용자 관찰로 판단합니다.

## 바꾸지 않는 것
원본 측정의 의미, 등록·수신·이력 저장 계약, 모델 계산과 입력 판정(`operations phm bind`와 같은 규칙), 기존 API.

## 데이터셋에 독립적인 탐색 계약

데이터셋 이름은 공통 메뉴나 기본 분석 방법을 고르지 않습니다. 사용자는
`상태 요약 → 이상 징후 → 신호 → 변화 분석 → 상태 전망`이라는 같은 과제 구조를
사용합니다. `이상 징후`의 기본 진입은 실행을 추측하지 않는 방법 선택이며,
두 종류의 측정을 함께 가진 설비에서는 비교·관계·전망에 사용할 근거를 직접
선택합니다. 실제로 존재하지 않거나 아직 읽지 못한 입력은 다른 데이터로
대체하지 않습니다.

분석 바로가기의 권위 있는 가능/대기/모델 연결/불가 판정 및 이동 대상은
`/api/v1/explore/capabilities`입니다. Web은 `target.view`, `target.goal`,
선택적으로 제공된 `target.data`를 안전한 내부 라우트로 변환하며,
설명용 `reason`만으로 다른 분석을 선택하지 않습니다. 저장 신호와 진동
파형은 동일한 '측정 신호' 업무 아래에서 각자의 시간/회차 축을 보존합니다.
사용 가능한 모델 결과나 계측 시간 정보가 없으면 그 부재와 다음 행동을
명시합니다. 화면 자동 검증은 동작과 정합성만 확인하며, 실제 사용자 이해도는
교차 데이터 사용성 관찰로 별도 평가합니다.
