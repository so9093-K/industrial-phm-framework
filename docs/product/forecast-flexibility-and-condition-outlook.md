# 미래 예측 유연화·상태 전망 콘텐츠

상태: Operations Web 제품 기능. 별도 사용자 역할 화면이나 새로운 RUL 학습 모델은 만들지 않는다.

## 사용 경험

1. 동일한 설비 화면의 `미래 예측`에서 측정값, 예측 기간, 선택적 관리 기준 및 그 방향(상한/하한)을 지정한다.
2. 실측·학습된 흐름·예측을 구별해 표시한다. 기본 그래프는 측정 및 예측 값의 변화를 중심으로 그리며, 멀리 떨어진 관리 기준은 범위 밖으로 표기한다. `관리 기준 포함 보기`로 전체 축을 확인할 수 있다.
3. `예측 설정 및 상세 분석`을 열면 추세 민감도, 변화점 탐색 범위, 학습 데이터 개수, 반복 패턴, 과거 검증 세부 지표를 확인하고 변경할 수 있다. 전문 사용자 역할 구분은 없다.
4. 이전·현재 설정의 예측을 비교할 수 있다. 여러 과거 시점 비교는 상세 보기에서 명시적으로 실행한다.
5. 상태 전망에는 최근 관측 변화, 저장 측정의 모델 없는 MAD 기준 이탈 구간 요약(근거가 단일한 경우), 미래 예측 변화, 선택한 관리 기준과 현재 거리, 예측선 기준의 잔여 시간·획득 수가 함께 표시된다.
6. 신호 탐색·모델 없는 이상 탐지에서 선택 신호와 비교·변화 구간을 넘겨 미래 예측으로 이동한다. 선택 구간은 참고 근거로 표시하며, 임의로 Prophet 학습 구간으로 사용하지 않는다. 다른 자산의 데이터로 자동 변경하지 않는다.

## 계산 계약

- `GET /api/v1/forecast`는 이전과 동일한 기본값으로 작동한다.
- `GET /api/v1/forecast/options`에 `kind`, `series`와 선택적 `training_points`, `assumed_period_seconds`를 전달하면 해당 신호의 실제 유효 학습 범위에서 가능한 시간 예측 기간을 `selection.horizons`로 제공한다. 화면 버튼도 이 결과를 사용한다.
- 선택값: `changepoint_prior_scale` (0.001–0.5, 기본 0.05), `changepoint_range` (0.5–0.95, 기본 0.9), `training_points` (20–1000), `seasonality=auto|off`, `backtest=one|multi`.
- 진동 획득 이력의 `horizon=count&horizon_count=N` (1–2000)은 획득 순서 기준 예측이다. 현재 획득을 포함해 정수 획득 위치 N+1개를 예측하며, 최소 기록 조건은 기존과 동일하게 유지한다. 선택적 `assumed_period_seconds` (1–86400)는 원본을 바꾸지 않는 가정이다.
- `recorded_period_seconds`와 `time_basis=recorded|assumed|ordinal`을 결과에 남긴다. 설비 개요의 미래 예측 가능 여부에서도 획득 개수 모드의 지원 여부를 반영한다. 시간 간격이 없더라도 획득 순서가 있으면 count 예측을 제공할 수 있다.
- 실제 데이터 길이·시간 범위와 예측 기간 간 기존 최소 조건(20개 관측, 기간의 2배 이력)은 유지한다. 최근 학습 구간을 줄인 경우도 다시 검사한다.
- 설비의 획득 결과 총 개수가 아니라, **선택 특징에 실제로 존재하는 유한한 수치**를 기준으로 가능 여부를 판단한다. API의 획득 특징별 `valid_points`와 `count_forecast`는 예측 계산에서 사용하는 최대 1,000개 샘플을 기준으로 하고, 유효 값이 20개 미만인 특징은 예측 선택 목록에서 제외한다. 기록은 남아 있지만 선택 가능한 특징이 없으면 그 이유를 표시한다.
- 과거 검증은 해당 과거 시점까지의 학습 자료만 사용한다. 다중 컷오프는 세 시점을 상한으로 별도 요청하며 과거 구간에 모델을 재학습한다.
- 기본 예측은 조회 요청에 즉시 계산하며 결과·작업을 새 DB에 보존하지 않는다.

## 표현 경계

- 과거 검증 지표는 관측된 비교 사실로 제공한다. 모델의 가치나 일반적인 정확도를 한 번의 결과로 단정하는 문구를 쓰지 않는다.
- 80% 예측 범위는 명목 구간 폭이며 실제 관측값 적중률과 구별한다.
- 관리 기준은 상한(이상) 또는 하한(이하)을 명시적으로 선택한다. 마지막 실측값을 기준으로 이미 도달했는지 판단하고, 모델 예측 시작값이 그와 다를 경우 별도 예상 도달로 보여준다.
- Prophet의 추세 성분 변화와 최종 예측값의 시작~종료 변화는 서로 다른 값으로 표시한다.
- 이상 구간은 관측·모델이 찾은 변화이고, 곧바로 고장 판정이 아니다.
- 상태 전망의 `기준 도달까지 잔여 시간·획득 수`는 사용자가 선택한 관리 기준에 대한 시나리오 계산이다. 실제 물리적 고장까지 남은 수명을 자동 산출하는 것이 아니며, 폐기된 RUL 모델을 복원하지 않는다.
- 추세 민감도나 간격 가정 변경에 따라 예측은 바뀔 수 있다. 결과는 설정과 근거를 함께 보여준다.

## 설정별 화면 예시

2026-10-15 Chromium 캡처. 같은 XJTU-SY `Bearing1_1`의 저장된 수평 진동 RMS
123개 획득(#1–#123)을 사용했다. 원본의 획득 간격은 60초이며, 캡처용 작업공간에
기존 분석 결과를 복사했다. 원본 파형·연구 모델·측정값은 변경하지 않았다.
1280px 화면의 미래 예측 영역을 캡처했으며, 마지막 예시는 390px이다.

공통 설정은 관리 기준 8, 추세 민감도 0.05, 변화점 범위 0.9, 전체 123개 학습,
1시간 예측, 기록된 획득 간격 사용이다. 표에는 이 설정과 달라진 항목을 적었다.

| 화면 | 바꾼 설정 | 확인할 내용 |
| --- | --- | --- |
| [기본값·관리 상한](images/forecast/default-upper.png) | 상한 8 | 마지막 실측 7.268과 종료 예상 8.283, 예측선의 상한 도달을 구분 |
| [민감도·변화점 범위 변경](images/forecast/sensitivity.png) | 민감도 0.2, 변화점 범위 0.95 | 이전 기본 예측선과 변경 후 예측선 비교. 종료 예상은 8.283 → 15.258로 달라짐 |
| [최근 학습·획득 수 예측](images/forecast/recent-count.png) | 최근 60개(#64–#123), 민감도 0.1, 미래 20개 획득 | 종료 예상 5.401은 마지막 실측 7.268보다 낮지만 모델 예측선 자체는 상승함. 두 비교를 같은 ‘증가’로 표현하지 않음 |
| [관리 하한](images/forecast/lower-limit.png) | 하한 8 | 마지막 실측 7.268이 이미 하한 이하인 상태와 앞으로의 예측을 구분 |
| [획득 간격 가정](images/forecast/assumed-interval.png) | 가정 간격 120초 | 같은 1시간 예측이 30개 획득 앞(#153)까지로 바뀜. 원본 간격 60초를 수정한 것이 아님 |
| [모바일 획득 수 예측](images/forecast/mobile-count.png) | 390px, 미래 30개 획득, 가정 간격 120초 | 획득 개수·가정 간격·예측 범위·관리 기준과 현재 거리를 확인 |

이 예시는 설정에 따른 화면과 계산 결과의 차이를 보여준다. 특정 설정의 우수성이나
현장 예측 정확도를 입증하지 않는다. 예측선 변화는 모델 시작값~종료값의 차이이며,
마지막 실측값 대비 변화와 다를 수 있다. 이 경우 상세 보기의 실측·예측 시작값 차이와
그래프를 함께 확인한다. 예측 범위는 재계산 시 달라질 수 있다.

## 테스트 범위

- 기본 예측 API 호환, 파라미터 경계값·비정상 값 거부
- 학습 구간 제한 및 동일 설정을 적용한 과거 예측 검증
- 획득 순서와 원본/가정 획득 간격 분리
- Y축·관리 기준 표기, 상세 설정, 상태 전망
- 동일 설비에서 신호 탐색·이상 탐지·미래 예측 간 이동
- 브라우저 390px / 1280px 회귀, 상·하한 기준, EDA 구간 전달, 짧은 획득 기록의 개수 예측 진입 및 기존 모델·CSV·OPC UA 경로 유지
- 별도 GitHub Forecast acceptance 워크플로에서 예측 API 통합 테스트와 Playwright 브라우저 테스트를 실행

기존 수집 내구성/AI-Hub 이상 탐지 성능 관련 이슈는 본 UI 콘텐츠 개발과 분리한다.
