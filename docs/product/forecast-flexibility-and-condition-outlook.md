# 미래 예측 유연화·상태 전망 콘텐츠

Operations Web의 예측 설정·그래프 계약입니다. 상태 전망의 기준 도달 계산은 [상태·잔여수명 전망](condition-and-rul-outlook.md)을 따릅니다.

## 사용 경험

1. 동일한 설비 화면의 `미래 예측`에서 측정값, 예측 기간, 선택적 관리 기준 및 그 방향(상한/하한)을 지정한다.
2. 실측·학습된 흐름·예측을 구별해 표시한다. 기본 그래프는 측정 및 예측 값의 변화를 중심으로 그리며, 멀리 떨어진 관리 기준은 범위 밖으로 표기한다. `관리 기준 포함 보기`로 전체 축을 확인할 수 있다. 같은 서버 응답에서 마지막 실측·중심 예측 종료의 값을 바로 옆에 설명하고, `실측·예측 대표값 표`에서 마지막 실측·예측 시작·예측 종료의 위치·중심값·구간 상하단을 키보드로 확인한다.
3. `예측 설정 및 상세 분석`을 열면 추세 민감도, 변화점 탐색 범위, 학습 데이터 개수, 반복 패턴, 과거 검증 세부 지표를 확인하고 변경할 수 있다. 전문 사용자 역할 구분은 없다.
4. 설정을 바꾸고 명시적으로 다시 계산할 수 있다. 여러 과거 시점 비교는 예측 계산 설정에서 선택해 실행하고 결과 표에서 오차·마지막 값 유지 기준·범위 내 실제값을 확인한다. 이전 설정의 그래프를 겹쳐 그리는 기능은 현재 업무 UI에서 제공하지 않는다.
5. 상태 전망에는 최근 관측 변화, 저장 측정의 모델 없는 MAD 기준 이탈 구간 요약(근거가 단일한 경우), 미래 예측 변화, 선택한 관리 기준과 현재 거리, 예측선 기준의 잔여 시간·획득 수가 함께 표시된다.
6. 신호 탐색·모델 없는 이상 탐지에서 선택 신호와 비교·변화 구간을 넘겨 미래 예측으로 이동한다. 선택 구간은 참고 근거로 표시하며, 임의로 Prophet 학습 구간으로 사용하지 않는다. 다른 자산의 데이터로 자동 변경하지 않는다.

## 계산 계약

- `GET /api/v1/forecast`는 선택한 설비·신호·기간에 대해 예측값과 예측 범위를 제공한다.
- `GET /api/v1/forecast/options`에 `kind`, `series`와 선택적 `training_points`, `assumed_period_seconds`를 전달하면 해당 신호의 실제 유효 학습 범위에서 가능한 시간 예측 기간을 `selection.horizons`로 제공한다. `selection.kind/series`는 확인한 대상을 명시한다. 시계열 전망 화면은 초기 진입·신호 변경·학습 개수 변경 시 이 결과로 기간과 계산 버튼을 갱신한다. 설비 전체의 기록 길이를 선택 신호의 계산 가능 조건으로 사용하지 않으며, 확인 중에는 계산을 시작하지 않는다.
- 선택값: `changepoint_prior_scale` (0.001–0.5, 기본 0.05), `changepoint_range` (0.5–0.95, 기본 0.9), `training_points` (20–1000), `seasonality=auto|off`, `backtest=one|multi`.
- 진동 획득 이력의 `horizon=count&horizon_count=N` (1–2000)은 획득 순서 기준 예측이다. 현재 획득을 포함해 정수 획득 위치 N+1개를 예측하며, 최소 기록 조건은 기존과 동일하게 유지한다. 선택적 `assumed_period_seconds` (1–86400)는 원본을 바꾸지 않는 가정이다.
- `recorded_period_seconds`와 `time_basis=recorded|assumed|ordinal`을 결과에 남긴다. 설비 개요의 미래 예측 가능 여부에서도 획득 개수 모드의 지원 여부를 반영한다. 시간 간격이 없더라도 획득 순서가 있으면 count 예측을 제공할 수 있다.
- 실제 데이터 길이·시간 범위와 예측 기간 간 기존 최소 조건(20개 관측, 기간의 2배 이력)은 유지한다. 최근 학습 구간을 줄인 경우도 다시 검사한다.
- 설비의 획득 결과 총 개수가 아니라, **선택 특징에 실제로 존재하는 유한한 수치**를 기준으로 가능 여부를 판단한다. API의 획득 특징별 `valid_points`, `valid_span_steps`, `count_forecast`는 예측 계산에서 사용하는 최대 1,000개 샘플을 기준으로 하고, 유효 값이 20개 미만인 특징은 예측 선택 목록에서 제외한다. 미래 획득 수의 기본값도 선택 특징의 유효 획득 범위를 기준으로 정한다. 기록은 남아 있지만 선택 가능한 특징이 없으면 그 이유를 표시한다.
- 과거 검증은 해당 과거 시점까지의 학습 자료만 사용한다. 다중 컷오프는 세 시점을 상한으로 별도 요청하며 과거 구간에 모델을 재학습한다.
- 기본 예측은 조회 요청에 즉시 계산하며 결과·작업을 새 DB에 보존하지 않는다.

## 표현 경계

- 과거 검증 지표는 관측된 비교 사실로 제공한다. 모델의 가치나 일반적인 정확도를 한 번의 결과로 단정하는 문구를 쓰지 않는다.
- 80% 예측 범위는 명목 구간 폭이며 실제 관측값 적중률·관리/종료 기준 도달 확률·고장 확률과 구별한다. 기본 그래프 바로 아래에서도 같은 의미를 설명한다.
- 관리 기준은 상한(이상) 또는 하한(이하)을 명시적으로 선택한다. 마지막 실측값을 기준으로 이미 도달했는지 판단하고, 모델 예측 시작값이 그와 다를 경우 별도 예상 도달로 보여준다.
- Prophet의 추세 성분 변화와 최종 예측값의 시작~종료 변화는 서로 다른 값으로 표시한다.
- 이상 구간은 관측·모델이 찾은 변화이고, 곧바로 고장 판정이 아니다.
- 기준까지의 잔여 시간·획득 수는 사용자가 정한 기준에 대한 계산이다. 종료 기준까지의 거리를 잔여수명으로 부른다([ADR-0027](../adr/0027-condition-and-remaining-life-outlook-from-stored-analyses.md)). 폐기된 RUL 모델은 복원하지 않는다.
- 추세 민감도나 간격 가정 변경에 따라 예측은 바뀔 수 있다. 결과는 설정과 근거를 함께 보여준다.


## 2026-11-05: 짧은 예측과 모델 시작 수준의 해석

- 시계열 집계값은 해당 집계의 마지막 관측 시각에 놓는다. 집계 구간 중간 시각을 사용해 이미 학습에 포함된 측정보다 앞에서 예측을 시작하지 않는다. 출처·측정 위치·해석별 독립 집계를 공유하며 집계 간격과 사용한 값 수를 표시한다.
- 최근 실측/집계값, 모델이 과거에 학습한 값, 미래 예측값을 각각 구분한다. 마지막 집계값과 모델 시작값의 차이를 그대로 표시하고, 예측값이나 범위를 마지막 실측에 맞춰 이동시키지 않는다. 최근 표시 구간의 범위와 모델 시작 수준이 다르면 그 사실을 안내한다.
- 요청한 예측 기간에 검증 값 5개가 없지만 충분한 학습 자료가 있으면 마지막 5개 집계값을 가려 과거 검증한다. `backtest.hidden_seconds`는 실제 검증 기간, `requested_seconds`는 요청한 예측 기간이다. 둘이 다르면 해당 기간의 직접적인 예측 성능 검증으로 표현하지 않는다.
- 측정 횟수 전망에서도 요청한 횟수·검증 측정값 개수·실제 검증 범위를 함께 표시한다. 검증 범위는 실제 검증 기간을 계산에 사용한 측정 간격으로 나눈 횟수이며, 결측이 있으면 측정값 개수와 다를 수 있다. 예를 들어 1회 앞을 요청하고 5회 구간에서 검증했다면 그 차이를 알린다. 시간 간격 정보가 없는 기록에서는 내부 계산용 간격을 실제 시간으로 표시하지 않는다.
- 같은 과거 구간의 마지막 값 유지보다 모델 오차가 큰 경우 추세 판단 보류를 표시한다. 수치 오차 수준의 차이는 제외한다. 이 비교만으로 다른 시점의 예측 정확도나 설비 상태를 판정하지 않는다.
- 집계 시각 교정은 수치 입력 버전을 바꿀 수 있다. 기존 저장 검토의 계산 결과와 시각은 보존하며, 새 계산으로 덮어쓰지 않는다.

- 같은 관측 집합의 병렬 집계가 서로 다른 수치 입력 버전을 만들지 않도록, 평균 집계 내부에서 원본 근거 ID 순서를 고정한다. 입력 버전의 정밀도를 낮추거나 실제 값 변경을 무시하지 않는다. [DuckDB의 순서 의존 집계 설명](https://duckdb.org/docs/1.5/sql/functions/aggregates)을 따른다.
