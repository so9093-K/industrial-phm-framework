# 데스크톱의 변화 조사 화면

1440×900과 1280×900에서 설비의 변화와 실제 값을 먼저 읽고 필요한 분석으로 이어간다. 화면마다 함께 비교할 정보를 정한다. 모든 분석에 전체 시간축과 고정 설정 열을 붙이지 않는다.

관측에서 조사로 이어지는 [제품 시나리오와 구현 범위](monitoring-scenarios.md)를 함께 따른다. 최근 관측은 입력 프로토콜과 별개로 기존 저장 측정을 읽으며, 1분 주기와 고정한 조사 구간·비교 기간을 지원한다.

## 모니터링

첫 화면은 데이터셋 관제다. 한 데이터셋의 설비를 한 줄씩, 같은 신호 묶음(R·S·T상, 진동 수평·수직)과 같은 규칙의 그래프로 늘어놓고, 저장 기록은 데이터셋 단위로 재생한다([배치와 재생 규칙](monitoring-scenarios.md#화면의-역할과-배치)). 조사 화면 위쪽의 설비 선택 줄은 설비 이름과 번호만 둔다. 등록된 이름을 우선하며 `Bearing1_1` 같은 공개 데이터 이름만 읽기 쉽게 바꾼다. 링크와 저장 데이터는 원래 ID를 유지한다. 과거 계측 기록에는 마지막 측정 연도를 표시한다. 모델 결과는 같은 입력과 시점을 분석했을 때만 합쳐 설명한다.

최근 측정에서는 마지막 실제 값·단위·측정 시각과 최근 추이를 먼저 읽는다. 구간을 선택하면 선택 구간 평균과 조사 동작을 그래프 위에 표시하고 관측을 고정한다. ‘최근 관측으로’에서만 다시 따라간다. 과거 날짜를 현재로 바꾸지 않으며 현재 시각과 마지막 측정 시각 중 시간 기준을 선택한다.

기록 변화 조사는 관제 화면의 한 줄을 크게 연 화면이며 그래프 규칙(TrendChart)과 색이 같다. 1440×900 한 화면에 결론·그래프·근거·다음 동작이 들어오게 한다.

- 머리: '← 데이터셋 관제'와 설비 이름 한 줄, 그 아래 보기 전환과 재생 한 줄. 다른 설비는 데이터셋 관제에서 고른다.
- 결론 한 줄: 고른 신호와 처음 대비 크기(예: 'R상전압 · 초기보다 4.26 V(1.9%) 높음'), 기간·이어짐·운전 조건.
- 그래프: 같은 시기에 함께 변한 신호 중 단위가 같은 것은 한 그래프에 겹친다(R·S·T상은 관제 화면과 같은 색). 단위가 다른 것은 같은 시간축의 작은 그래프로 아래에 둔다(베어링: RMS 아래 첨도·왜도). 고른 신호에는 처음 범위(옅은 띠)·처음 수준(점선)·같은 운전 수준의 값(점)을 그린다. 운전 수준을 아는 출처는 그 아래에 칸마다 가장 오래 운전한 수준을 진하기로 칠한 띠를 둔다. 포인터를 올리면 그래프 위 값 줄이 그 시각의 상·축별 값으로 바뀌고, 같은 시간축의 다른 그래프에도 세로선이 선다.
- 오른쪽 칸: 고른 신호의 비교 구간 → 변화 구간 숫자, 같은 구간의 다른 신호(이름 · 비교 → 변화 한 줄씩), 전류 수준 비중 또는 진동·주파수 변화.
- 동작: 주요 동작 하나(채움)와 나머지(테두리)의 두 모양만 쓰며 같은 크기다. 분석 탭의 머리에는 '← 변화 조사'와 고른 변화만 둔다(설비 이름은 위 줄). 다른 시기의 변화나 상세 파형은 필요할 때 연다. 모델 점수와 모델 간 비교는 이상 징후 화면에서 필요할 때 확인한다. 관측 화면에서 모델별 초과 횟수를 나열하거나 점수 이력을 자동 조회하지 않는다. 측정 공백은 연결하지 않으며 커서는 실제 측정만 고른다.

모니터링은 전망을 자동 계산하지 않는다. 관리 기준과 예측 기간은 전망 화면에서 설정한다. 판단과 메모도 요청했을 때 기존 대화상자에서 작성한다. 닫았다 다시 열어도 입력 중인 내용은 유지하며, 다른 변화의 초안과 섞지 않는다.

## 상세 분석

분석을 열면 본문 전체 폭을 사용한다. 상단에는 설비·기록 정보, 관측에서 선택한 변화, 모니터링 복귀와 분석 탭을 둔다. 관측에서 고른 변화는 조사 출발점을 뜻한다. 이후 편집한 A/B 기간과 혼동하지 않는다. 이전 관측 컴포넌트를 숨긴 채 계산을 계속 실행하지 않는다.

- 원본 신호: 관련 신호를 함께 선택하면 같은 단위의 신호는 겹치고 전압·전류처럼 단위가 다르면 시간축을 맞춘 별도 그래프로 표시한다. 구간 선택을 공유한다. 그래프 옆에서 선택한 구간의 평균·직전 차이 또는 선택한 진동 측정값을 읽고 같은 대상의 후속 비교로 이어간다. 출처·측정 항목 설명은 그래프 뒤에서 확인한다.
- 이상 점수: 모델 고유 이상 점수·기준선 그래프와 선택 측정의 값 비교를 나란히 둔다. 이전·다음 버튼과 그래프의 방향키/Home/End로 저장된 측정을 고른다. 선택한 모델 하나를 중심으로 조사한다. 다른 모델과의 비교는 별도 동작으로 열고 닫힌 동안 조회하지 않는다. 모델 간 점수 크기나 초과 횟수를 설비 위험 순위·모델 성능으로 취급하지 않는다. 학습하지 않은 운전 조건과 부분 조회 상태는 해당 결과에서 밝힌다.
- 기간 비교: 비교 대상·기간·변경 동작을 한 줄로 묶고 같은 신호의 추이와 분포를 나란히 배치한다. 설정 컴포넌트가 결과 화면의 첫 행을 강제하지 않는다.
- 신호 관계: A/B 산점도를 같은 축으로 비교하고 선택 측정의 두 값을 옆에서 읽는다. 고른 측정은 모델과 원본으로 이어지며 키보드로도 선택한다. 상관계수만으로 원인을 단정하지 않는다.
- 주파수: 기간 평균 스펙트럼과 측정별 주파수 지도의 대역을 맞춘다. 측정 조사에서는 선택한 측정의 스펙트럼을 지도와 비교한다. 에너지 배율과 대역 비중을 시각적으로 우선한다.
- 3상 전력: 우선 확인 시점 주변의 추이와 선택한 시각의 R/S/T 값을 함께 보여 준다. 전체 기간으로 전환할 수 있고 점 선택만으로 그래프 범위가 움직이지 않는다.
- 전망·예상 여유: 그래프 옆에서 현장 기준과 적용 결과를 읽는다. 입력 중인 기준은 미적용 상태로 구분하며 그래프를 지우지 않는다. 실제 값·모델 학습값·미래 예측을 구분한다. 예측 활용을 보류해야 하는 경우 그래프 앞에서 알린다. 현장 기준까지의 조건부 예상 여유를 검증된 고장 수명으로 표시하지 않는다.

좁은 창에서는 필요한 비교를 한 열로 옮긴다. 휴대폰 배치를 늘려 PC 화면으로 쓰지 않는다.

## AI와 판단

변화 조사 화면의 'AI 해석' 버튼은 조사 영역 오른쪽 전체 높이에 대화창을 붙인다. 대화창은 고른 변화 하나에 묶이며, 맨 위에 그 변화(이름·구간)를 보여 무엇에 대해 묻는지 드러낸다. 지난 질문과 답이 말풍선으로 쌓이고 그 부분만 스크롤하며, 입력창은 아래에 고정한다. Enter로 보내고 Shift+Enter는 줄바꿈이며, 한글을 조합하는 중의 Enter는 보내지 않는다. 대화가 없을 때는 이 변화에 맞는 질문 두세 개를 보여 주고, 대화 뒤에는 아직 묻지 않은 질문을 입력창 위에 둔다. 기다리는 동안은 경과 초를 보여 멈춘 것과 구분한다.

답 아래에는 답이 근거로 쓴 사실이 번호와 함께 놓인다. 그래프에 그려진 변화는 그 선의 색과 이름으로, 운전 수준 비중은 비교 구간·변화 구간의 두 막대로, 운전 수준 흐름은 작은 띠로, 주파수는 두 구간의 대역 비중으로 보인다. 근거에 포인터를 올리거나 눌러 고정하면 왼쪽 그래프가 그 선·변화 구간·운전 수준 띠만 남기고 나머지를 옅게 한다. 답은 판단 메모로 옮기거나 복사할 수 있다. 질문의 자료 범위와 후속 분석은 해당 기록과 재생 위치를 가리킨다. 답변 대기 중에도 다음 질문을 쓸 수 있고, 닫았다 다시 열어도 초안과 생성 상태를 복원한다. 화면 곳곳에 같은 채팅이나 해설을 복제하지 않는다.

모델에 보내는 사실은 화면과 같은 기준이다. 시각은 그래프와 같은 한국 시간 표기(예: 10월 4일 09:19)로, 운전 수준은 그래프 범례와 같은 이름(예: 약 11 A 운전)으로 쓴다. 같은 운전 수준끼리 비교한 값은 그렇다고 밝힌다. 화면이 같은 시기로 묶어 함께 그린 변화와 그 시작 순서, 운전 수준별 비중(비교 구간 → 변화 구간), 변화 앞뒤의 운전 수준 흐름, 진동 특징의 일반적인 뜻을 함께 보낸다. 먼저 시작한 변화를 뒤 변화의 원인으로 단정하지 않는다. 로컬 모델이 답 형식을 되풀이하거나 답 뒤에 글을 덧붙여도 그 안의 답을 읽고 모든 값을 똑같이 검사한다.

진동 변화 질문은 실제 변화의 시작·지속·주파수 구성을 중심으로 제안하며, 두 모델의 차이를 기본 조사 과제로 제시하지 않는다. 답변은 판단 메모 초안으로 옮길 수 있다. 모델 측정 질문은 선택한 측정·비교 측정에 연결된다. 생성 여부와 답변의 유용성은 별도로 확인한다. 계산 요약으로 대체된 답변을 LLM 응답으로 보고하지 않는다.
