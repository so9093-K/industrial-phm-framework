# 분석 화면 벤치마킹과 구성 개선 방향

2026-11-19 · 산업 시계열 분석, 관측 도구, 시각화 설계의 공식 자료 기준

## 핵심 판단

현재 분석 화면은 계산 결과를 설명하는 문서의 순서로 구성돼 있다. 제목과 분석 조건, 핵심 결과 문단, 그래프, 수치 목록, 추가 그래프, 해석, 후속 링크가 계속 쌓인다. 문장을 줄이거나 설정을 접어도 이 순서가 유지되면 긴 보고서처럼 읽힌다.

바꿔야 할 단위는 문구나 카드가 아니라 **하나의 현상을 살펴보는 작업 전체**다. 사용자는 그래프에서 변화가 드러나는 부분을 보고, 해당 구간이나 측정을 선택하고, 바로 연결된 비교 결과로 이해를 깊게 할 수 있어야 한다. 처음부터 모든 결과를 보여줄 필요는 없다. 중요한 해석 제약은 해당 결과와 함께 보여줘야 한다.

이 문서의 제안은 기존 계산을 활용하는 구성 변경이다. 새로운 위험 점수, 고장 판정, 검증 기록 시스템, 범용 대시보드 편집기를 제안하지 않는다.

## 확인 범위와 한계

- 사용자가 제공한 11개 화면 리뷰 전문과 주파수 화면 캡처를 읽었다. 리뷰에 적힌 모든 분석 수치를 이번에 독립적으로 재계산한 것은 아니다.
- `.other/img`의 모델 점수·주파수·기간 비교 화면을 읽기 전용으로 확인했다. 이 캡처를 최신 PR 실행 화면과 혼동하지 않았다.
- PR #731의 `7ea134d7` 빌드로 모델 점수와 주파수 화면을 직접 열어 확인했다. 사용자 서버의 GET 요청만 전달하는 임시 미리보기를 사용했다. 최신 구성에서도 화면의 중심이 무엇인지 더 명확히 정해야 한다는 판단이다. 이 두 화면을 확인한 사실로 전체 화면의 UX가 검증됐다고 주장할 수는 없다.
- 외부 제품은 공식 문서, 릴리스 안내, 공개 이미지를 조사했다. TrendMiner와 Datadog의 공개 화면 이미지를 직접 보았다. 유료 제품에 로그인해 실제 설비 데이터를 분석한 것은 아니다.
- 아래 두 주파수 구성 시안에는 로컬 서버가 계산한 Bearing1_1 결과를 사용했다. 시안은 제품에 배포한 화면이 아니다. 운영 데이터, LLM 설정, `.other`는 변경하지 않았다.

## 1. 외부 제품에서 배울 점과 그대로 가져오지 않을 점

### TrendMiner: 정렬된 신호와 구간 선택을 작업의 중심으로

2026.R3 Focus Chart 문서는 신호별 세로축과 공통 시간축을 사용하는 쌓인 추세, 전체 맥락을 보는 차트, 측정값을 읽는 커서를 설명한다. 실제 공개 화면에서도 설명문보다 신호 추세와 선택 범위가 넓은 공간을 차지한다. [공식 Focus Chart 안내](https://userguide.trendminer.com/2026.R3.0/en/focus-chart.html)

배울 점은 신호를 같은 그래프에 모두 겹치는 것보다 **서로 다른 단위의 신호를 같은 시간 위치에서 읽게 하는 것**이다. 공기압축기의 전류·전압·운전 수준을 연결할 때 적용할 수 있다. 신호 목록과 분석 메뉴가 많은 전문가용 화면 전체를 그대로 복제하면 처음 사용자의 부담은 커진다.

이 원칙은 최근 갑자기 생긴 유행이 아니다. TrendHub Next Generation의 변경 설명에도 쌓인 추세, 커서와 통계, 시간 범위 조작의 단순화가 등장한다. 우리에게 필요한 것은 오래 축적된 분석 상호작용을 제대로 적용하는 일이다. [변경 방향 안내](https://userguide.trendminer.com/2025.R2.0/en/main-differences-in-trendhub-next-generation.html)

### Seeq: 추세와 비교 결과를 가까이 두되, 목적에 따라 화면을 다르게

Summary Report는 추세와 통계를 나란히 배치하고, 기간별 결과를 겹치거나 나란히 비교하며, 히스토그램·상자 그림 등으로 분포를 확인하도록 구성한다. [공식 Summary Report 안내](https://support.seeq.com/latest/cloud/summary-report)

우리 프로젝트에서는 A/B 비교가 이미 강점이다. 새 요약 문단을 추가하기보다, 비교 수치와 그 차이를 보여주는 그래프를 한 묶음으로 유지하면 된다. 모델 화면은 점수와 해당 측정, 주파수 화면은 대역과 시간별 변화를 가까이 두는 식으로 적용해야 한다. 모든 화면을 같은 2열 카드에 넣는 규칙으로 일반화할 이유는 없다.

산점도에서 고른 점들을 시간 추세의 조건으로 연결하는 기능도 참고할 만하다. 선택이 다른 그래프의 조사 대상으로 이어지는 것이 핵심이다. [공식 산점도 선택 안내](https://support.seeq.com/latest/cloud/scatter-plot-selection-tool)

### DewesoftX 2026.1: 서로 연결돼야 하는 물리량을 함께 조작

2026-02-16 릴리스는 Order Analysis에 FFT 대 시간 워터폴을 통합하고, 올바른 속도 데이터와 연결하기 어려웠던 별도 모듈 구성의 문제를 설명한다. 시간 구간 마커를 여러 채널에 적용하는 개선도 포함한다. [공식 릴리스 안내](https://dewesoft.freshdesk.com/en/support/solutions/articles/14000162895-dewesoftx-2026-1-official-release)

배울 점은 3D 그래프나 기능 수가 아니다. **서로 비교해야 하는 결과가 같은 선택 맥락을 공유해야 한다**는 점이다. 주파수 대역을 확대하면 평균 스펙트럼과 측정별 주파수 지도의 범위도 함께 바뀌어야 한다. 회전 속도와 같은 자료가 없는 기록에 오더 분석이나 결함 주파수 해석을 추가해서는 안 된다.

### Grafana: 화면을 유연하게 만들면서도 조사 기능 자체의 복잡성을 경계

2026-04-08 Dynamic Dashboards 정식 제공 안내에는 탭·행·조건부 표시뿐 아니라 두 툴바를 하나로 줄이고, 필요한 때만 측면 조작부를 여는 변화가 포함돼 있다. [공식 GA 안내](https://grafana.com/whats-new/2026-04-08-dynamic-dashboards-is-now-generally-available/)

이는 모든 결과를 한 페이지에 동시에 노출하는 방식에서 벗어날 근거가 된다. 다만 우리 제품에 범용 배치 편집기를 만드는 근거는 아니다. 사용자가 수행하는 분석 작업에 맞춘 기본 배치가 먼저다.

더 중요한 반례도 있다. Grafana는 2025-12-04 공지에서 Drilldown Investigations의 사용률이 낮고 추가 패널이 복잡성을 만들었다며 2026년 1월 제거를 안내했다. 일반 Explore·Drilldown 전체나 별도의 Assistant Investigations가 철회됐다는 뜻은 아니다. [공식 제거 안내](https://grafana.com/blog/removal-of-drilldown-investigations-in-grafana-what-you-need-to-know/)

따라서 ‘조사’라는 이름의 패널, 메모 모음, 근거 목록을 추가하면 가치가 생긴다는 가정부터 경계해야 한다. 현재 제품에 필요한 것은 선택한 변화의 이해가 빨라지는 경험이다.

### Datadog: 선택한 조사 맥락 보존과 작은 그래프의 비교

Metrics Explorer는 조사 세션을 보존·재개하고, 분할 그래프와 시간 범위 조작을 제공한다. 공개 화면에는 쿼리 조작과 시계열 탐색이 함께 있다. [공식 Metrics Explorer 안내](https://docs.datadoghq.com/metrics/explorer/)

재방문했을 때 선택한 모델·측정·기간이 유지되는 경험을 배울 수 있다. 반면 많은 쿼리 입력칸과 내부 식별자를 PHM 사용자에게 노출하는 구성은 가져오지 않는다. 개발자 관측 도구가 제공하는 기능을 산업 분석 화면의 사용성으로 곧바로 환산할 수는 없다.

### Honeycomb: 선택 영역과 비교 결과에 연결된 AI

2026-08-05 AI BubbleUp 안내는 히트맵에서 선택한 영역과 비교 집단의 차이를 분석하고 AI가 설명하는 흐름을 다룬다. 통계적으로 다른 속성과 원인으로 중요한 속성이 같지는 않다는 한계도 설명한다. [공식 AI BubbleUp 소개](https://www.honeycomb.io/blog/introducing-ai-bubbleup)

우리에게 유용한 부분은 선택한 현상과 계산된 비교가 AI 질문의 출발점이 된다는 점이다. ‘AI에게 질문하기’가 별도 세계로 이동하는 동작이어서는 안 된다. 전류 상승 구간이나 진동 변화 측정을 고른 상태에서, 무엇이 함께 달라졌고 다음에 어떤 비교가 필요한지 설명해야 한다. 소프트웨어 요청 추적에서 쓰는 원인 분석 표현을 베어링 고장 진단에 그대로 적용하지 않는다.

## 2. 시각화 설계 자료가 뒷받침하는 방향

IBM은 제목과 주석이 주요 발견을 전달하고, 직접 표기를 활용하며, 중요한 정보를 상호작용 뒤에만 숨기지 않도록 설명한다. 따라서 ‘800–1,594 Hz’를 문단에서만 설명할 것이 아니라 해당 대역 위에 표시해야 한다. [IBM Data Visualization Basics](https://www.ibm.com/design/language/data-visualization/design/basics/)

Michelin의 대시보드 원칙은 그래프가 보조 설명 없이도 이해될 수 있어야 한다는 방향을 제시한다. 이 제품에서는 차트의 축·단위·비교 대상이 짧고 명확해야 한다는 뜻으로 적용한다. 설명을 모두 지우거나 모든 수치를 카드로 만드는 뜻은 아니다. [Michelin 대시보드 설계 원칙](https://designsystem.michelin.com/data-visualization/design-guidelines/principles-of-a-dashboard)

Power BI의 설계 안내는 요약 화면에서 핵심 정보를 빠르게 읽고 상세 보고서로 이어가는 구분을 강조한다. 이를 ‘모든 분석을 한 화면에 구겨 넣는다’로 해석해서는 안 된다. PC 화면의 목적은 글씨를 줄여 스크롤을 없애는 것이 아니라, 비교할 자료를 충분한 크기로 함께 보게 하는 것이다. [Microsoft 대시보드 설계 안내](https://learn.microsoft.com/en-us/power-bi/create-reports/service-dashboards-design-tips)

## 3. 지금 화면의 구조적 원인

### 분석 방법이 페이지 구성의 단위가 됨

각 계산의 출력마다 설명·표·차트·상세를 붙인다. 계산이 추가될수록 페이지가 길어지고, 어떤 계산을 먼저 보느냐가 사용자가 무엇을 이해하느냐를 좌우한다. 요약 상자를 크게 만들어도 같은 정보를 문단으로 압축했을 뿐이면 독해 부담은 남는다.

### 그래프의 선택이 다른 결과를 움직이지 못함

이동 링크는 있어도 선택한 대역·측정·기간이 다른 그래프를 즉시 바꾸는 경험은 약하다. 사용자가 스스로 스크롤하며 문장 속 숫자와 그래프 위치를 연결한다. 이 관계를 구현하지 않고 설명을 더 붙여 해결하려 했다.

### 모든 화면에 비슷한 틀을 적용함

상단 결과 문단과 공통 설정 열은 구현에는 편하지만, 주파수 대역 조사·모델 측정 선택·운전 조건 비교는 서로 다른 작업이다. #731의 설정 열 제거와 인접 배치는 필요한 수정이지만, 그것만으로 새 분석 경험이 완성되지는 않는다.

### 정확한 사실의 나열과 사용자의 이해를 같은 것으로 취급함

예를 들어 RMS 증가, 모델별 반응 차이, 대역 비중 변화, 예측 성능 부족은 각각 사실이다. 사용자가 이 사실을 연결해 무엇을 알 수 있는지까지 화면에서 드러나야 한다. 다만 이를 임의의 원인·위험 등급으로 합쳐서는 안 된다.

## 4. 화면별로 중심 작업을 다시 정하기

| 화면 | 사용자가 먼저 알아야 하는 것 | 중심 시각화·조작 | 기본 화면에서 줄일 것 |
| --- | --- | --- | --- |
| 관측 현황 | 어느 설비의 어떤 현상을 먼저 볼지 | 주요 변화와 최근 측정을 구분한 짧은 행, 명확한 조사 동작 | 모델별 긴 문장, 운영 메타데이터, 반복된 확인 건수 설명 |
| 설비 요약 | 선택한 변화가 실제로 어떤 모습인지 | 전후 맥락을 포함한 큰 추세, 관련 비교로 이어지는 선택 | 같은 크기의 여러 변화 카드, 판단 양식과 AI의 상시 노출 |
| 원본 신호 | 언제 무엇이 함께 변했는지 | 공통 시간축의 신호별 차트, 축에 맞는 구간 선택 | 그래프 전 장문 안내, 내부 출처 코드 |
| 모델 점수 | 어느 측정에서 모델이 반응했고 실측은 어땠는지 | 점수 추세와 선택 측정의 특징·파형을 가까이 | 전체 모델 비교표 선행, 모든 특징값 행, 점수 배율 통합 순위 |
| 두 기간 비교 | 값의 수준·퍼짐이 얼마나 달라졌는지 | 대표 차이와 두 기간의 추세·분포 | 좋은 기존 그래프의 재설계, 기준이 다른 비율을 동등하게 강조 |
| 신호 관계 | 관계의 형태가 어떻게 달라졌는지 | 같은 축의 A/B 산점도, 점 선택과 원본 연결 | 상관계수만 큰 제목으로, 긴 특징 사전 설명 |
| 주파수 | 어느 대역이 언제부터 달라졌는지 | 확대 대역과 시간별 지도 연동, 측정 선택 | 피크·대역 순위 나열, 두 방향의 동일 구조 반복 |
| 3상 전력·불평형 | 운전 수준 변화와 상간 차이가 언제 겹쳤는지 | 같은 시간축의 전류와 불평형 추세, 확인 시점 선택 | 의미가 다른 네 지표의 동일한 수치 카드 |
| 전망 | 이번 예측을 어디까지 활용할 수 있는지 | 실측·예측·검증의 분명한 구분, 유용성에 맞는 강조 | 성능이 나쁜 미래 곡선의 과도한 강조, 중복 요약 |

특히 모델 학습에 드물었던 운전 상태라는 제약은 해당 모델 결과 가까이에 둬야 한다. 불리한 과거 검증 결과도 전망 제목 근처에서 이해할 수 있어야 한다. 중요한 제약을 하단 기술 상세로 모두 보내는 방식은 단순화가 아니다.

## 5. 같은 주파수 데이터로 만든 두 구성

두 구성 모두 Bearing1_1의 비교 기준 1–37회와 변화 구간 72–123회를 사용한다. 서버가 각 기간에서 고른 8회 파형의 평균 스펙트럼과 60개 측정의 주파수 지도를 사용했다. 측정 시각을 알 수 없는 기록이므로 가상의 날짜를 붙이지 않았다.

### 변화 대역 중심

전체 에너지의 B/A 배율과 특정 대역의 비중을 서로 다른 표시로 구분한다. 평균 스펙트럼 아래에 주파수 지도를 같은 가로축 위치로 맞춘다. 처음에는 변화 대역 주변을 보여주고 전체 주파수로 돌아갈 수 있게 한다.

이 구성의 목적은 ‘어느 대역이 커졌나’와 ‘그 대역이 언제 달라졌나’를 같은 시선에서 확인하는 것이다. 평균 스펙트럼은 측정을 골라도 다른 의미의 곡선으로 바뀌지 않는다.

### 측정 선택 중심

왼쪽 주파수 지도에서 측정을 고르면 오른쪽 스펙트럼이 즉시 바뀐다. 키보드로 조작할 수 있는 측정 선택 목록도 제공한다. 시계열 지도와 선택 측정 곡선은 같은 dB 기준을 사용한다.

이 구성의 목적은 변화 직전·직후의 개별 측정이 어떻게 다른지 조사하는 것이다. 평균 비교와 개별 측정을 같은 그래프에 무분별하게 겹치지 않는다.

### 수치의 의미를 섞지 않기

- 전체 에너지 배율은 기간 B와 A의 전체 에너지 비교다.
- 대역 비중은 각 기간 전체 에너지 중 해당 대역이 차지하는 몫이다.
- 상대 dB는 정해진 참조 세기 대비 주파수별 값을 로그로 표시한 것이다.

이 세 가지는 같은 변화량이 아니다. 스펙트럼을 확대해도 상대 dB의 참조값을 매번 다시 잡지 않는다. 주파수 지도의 색 기준과 평균 스펙트럼의 기준이 다르면 이를 구분한다. 배율이 크다는 사실만으로 고장 원인을 주장하지 않는다.

시안에서 긴 설명을 덜어낸 것은 설명의 역할을 없애기 위해서가 아니다. 변화 대역 표시, 같은 축, 막대와 곡선의 구분으로 설명하던 관계를 화면에서 읽게 하기 위해서다. 계산 조건은 짧은 상세로 남긴다.

## 6. 생성형 AI의 역할

현재 화면을 다시 읽어 주는 답변만으로는 충분하지 않다는 리뷰에 동의한다. AI 질문의 단위도 ‘설비의 모든 정보’보다 현재 선택한 현상이어야 한다.

예를 들어 진동 변화에서 모델 반응이 갈렸다면 같은 측정·같은 구간의 실측 특징, 모델 결과, 대역 비교를 묶어 질문할 수 있어야 한다. 답변은 무엇이 함께 달라졌는지, 모델 결과만으로 무엇을 설명할 수 없는지, 다음에 어떤 비교를 하면 도움이 되는지를 연결해야 한다. 학습 자료가 부족하면 그 이유를 아는 척해서는 안 된다.

UI에서는 별도 채팅창을 상시 크게 노출하기보다, 고른 현상에 연결된 질문 동작과 필요한 답변을 제공한다. 답변의 후속 동작이 실제 그래프의 대역·측정·비교 기간을 선택하도록 연결돼야 한다. 메모로 옮기기는 이 이해 과정 뒤에 따른다.

도구의 AI가 원자료를 자동으로 모두 본다고 가정해서도 안 된다. Seeq 공식 안내도 일부 Actions Agent가 원시 시계열을 볼 수 없다는 범위를 구분한다. 우리 제품 역시 AI에 전달한 자료에 맞춰 답변 범위를 정해야 한다. [Seeq AI Assistant 안내](https://support.seeq.com/latest/cloud/seeq-ai-assistant)

좋은 답변의 기준은 문장 생성 성공이나 긴 분량이 아니다. 사용자가 질문 전에는 연결하지 못했던 분석 사실을 이해하고 다음 비교를 수행할 수 있는지다. 실제 LLM 서버 답변을 확인하는 작업은 시안 렌더링과 별개로 필요하다. 이번 외부 리서치에서 새 답변 품질을 검증했다고 주장하지 않는다.

## 7. 기술 선택: 먼저 구조를 정하고 작은 범위에서 비교

Vega-Lite의 선택과 매개변수는 그래프 간 연동을 설계할 참고가 된다. 이를 적용하려고 프런트엔드 전체를 다시 만들 필요는 없다. [선택 안내](https://vega.github.io/vega-lite/docs/selection.html), [매개변수 안내](https://vega.github.io/vega-lite/docs/parameter.html)

어떤 도구를 쓰더라도 설비·출처·측정 위치·신호·기간·모델·선택 측정·주파수 대역의 소유 관계가 분명해야 한다. 화면 안에서는 관련 선택을 연결하고, 후속 분석·재방문에서도 유지한다. 이것은 새 근거 저장 시스템을 만드는 일이 아니라 사용자가 조사 대상을 잃지 않게 하는 일이다.

## 8. 다음 작업의 범위와 완료 기준

1. **주파수 분석 한 흐름을 완성한다.** 변화 대역 보기 → 시간별 변화 확인 → 측정 선택 → 원본·모델 확인을 실제 데이터로 이어 본다. 평균과 개별 측정, 색과 세로축의 참조 기준을 섞지 않는다.
2. **공기압축기의 운전 조건 비교를 별도로 구성한다.** 같은 시간 위치의 전류·전압·불평형을 살펴보고, 운전 수준 구성 변화와 같은 조건 안의 변화를 구분한다. 네 개의 동일한 수치 카드에 또 설명을 붙이는 방식은 피한다.
3. **모델 결과와 전망의 정보 순서를 바로잡는다.** 선택 측정과 실측을 가까이 두고 학습 조건의 제약을 함께 읽게 한다. 유용성이 낮은 전망은 그럴듯한 미래 곡선을 화면의 주인공으로 만들지 않는다.
4. **설비 요약과 AI를 위 흐름에 연결한다.** 이미 있는 분석 사실이 한 현상으로 이어지게 하되, 모든 결과와 입력 양식을 다시 요약 화면에 쌓지 않는다.

주요 사용 환경은 PC다. 1280×900·1440×900에서 비교해야 하는 자료를 함께 보고 조작할 수 있는지가 우선이다. 좁은 화면의 넘침 방지는 기본적인 대응이며, PC 배치를 세로 카드로 쌓는 설계의 이유가 될 수 없다.

완료를 판단할 때는 다음 실제 동작을 확인한다.

- 설명 문단을 읽기 전에 어느 대역·구간이 다른지 그래프에서 찾을 수 있는가?
- 고른 측정과 오른쪽 비교 결과가 같은 대상을 가리키는가?
- 전체 기록을 놓치지 않고 확대·선택·복귀할 수 있는가?
- 다른 분석을 다녀와도 선택과 작성 중인 내용이 유지되는가?
- 모델의 학습 조건 차이와 전망의 낮은 성능을 결과보다 늦게 알아차리지 않는가?
- AI 답변 후 실제로 새 비교를 수행하거나 현상을 더 잘 설명할 수 있는가?

이번 시안은 브라우저에서 두 구성의 렌더링, 방향·주파수 범위·측정 선택의 반영, 밝은 화면과 어두운 화면을 확인했다. 이 확인은 동작과 배치에 관한 것이며 사용자 이해도나 제품 전체의 개선을 입증하지 않는다. 제품 코드의 새 배포·병합은 이번 리서치 범위에 포함하지 않았다.

## 리서치 이후의 구현

후속 구현에서는 두 시안을 주파수 분석의 ‘기간 비교’와 ‘측정 조사’로 연결했다. 비교에서는 에너지 배율과 대역 비중을 구분하고, 평균 스펙트럼과 주파수 지도의 축 위치를 맞춘다. 측정을 선택하면 지도와 개별 스펙트럼을 나란히 보며, 해당 작업에 필요하지 않은 기간 평균 수치는 반복하지 않는다. 평균과 개별 측정의 dB 참조값도 섞지 않는다.

방향·대역·측정·보기 방식·축 설정은 주소에 유지한다. 고른 측정으로 원본 파형·모델 결과를 열거나 A/B 중 한 기간만 바꿀 수 있다. 지도 조회가 실패하면 평균 비교는 계속 사용할 수 있지만 개별 측정 곡선으로 대신 표시하지 않는다. 계산 API는 변경하지 않았다.

Bearing1_1의 실제 응답으로 1280×900·1440×900을 직접 확인했다. 두 크기에서 비교 그래프는 약 455px부터, 지도는 약 718px부터 나타났으며, 측정 조사에서는 두 그래프가 약 370px부터 나란히 나타났다. 선택·방향 변경·재진입·좁은 화면의 넘침도 확인했다. 이 수치는 해당 기록의 기본 조건에서 측정한 배치이며 사용자 이해도에 대한 평가가 아니다.
